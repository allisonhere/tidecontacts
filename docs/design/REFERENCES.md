# Phase 4A visual reference library

The observations below are from rendered pages and actual interface images. Product screenshots and contact sheets were reviewed in private scratch storage; this repository only links to third-party sources. The captures under `screenshots/` show TideContacts or its fictional prototypes, not copied product images. None of these references is a claim that we tested the native third-party apps.

| **Bear:** [home](https://bear.app/), [Mac workspace](https://bear.app/images/home/hero_mac.jpg), [theme examples](https://bear.app/images/home/feature_spot_3.png) | Dark navigation, quiet preview list and light reading canvas have different weights. The earlier Linear [UI redesign](https://linear.app/now/how-we-redesigned-the-linear-ui) also shows both [light and dark in the same crop](https://webassets.linear.app/images/ornj730p/production/b7551ae44d0365c0ed87d7e5e23aeb0421233ba5-2352x1656.png). Both preserve the location, outline icons, and status semantics rather than inverting all colors together.

## Analytical and platform standards

| Reference and inspected evidence | Principle to adopt | Guardrail |
| --- | --- | --- |
| **Pentagram / IBM:** [case study](https://www.pentagram.com/work/ibm-data-visualization-guidelines), [graphic system](https://pentagram-production.imgix.net/0a275265-e3db-4ae1-8e1e-f2405e211695/gl_ibm_02.jpg), [IBM usage](https://www.ibm.com/design/language/data-visualization/design/usage/), [Watson composition](https://www.ibm.com/design/language/static/8417866f61ae6a3c028e6c0d5544ce43/92c65/IBM_Watson_Discovery_Demo.png) | The work distinguishes strong editorial marks from quieter visualization surfaces. In the Watson example, one explanatory area and thin chart rules coexist with prominent numeric values. Use a labelled baseline, exact amounts, and annotation where it changes a decision. | Do not import the IBM palette, brand shapes, adjacent donut, or mini-chart density. Never make a style mark carry the only distinction between two business states. |
| **Helios:** [data visualization](https://helios.hashicorp.design/patterns/data-visualization), [bar example](https://helios.hashicorp.design/assets/patterns/data-visualization/color-usage/data-visualization-example-vertical-bar-a627f6ffcc00cf94328d5c71e86dedae.png) | The chart has a specific measure as its title, subdued horizontal guides and a stronger selected bar. Actions sit outside the plot. | Use direct values/units and a keyboard-reachable record list. The example's lowest shown tick is 10,000; TideContacts value bars start at zero so their lengths honestly communicate relative magnitude. |
| **Apple HIG:** [index](https://developer.apple.com/design/human-interface-guidelines/), [split views](https://developer.apple.com/design/human-interface-guidelines/split-views), [sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars), [toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars), [menus](https://developer.apple.com/design/human-interface-guidelines/menus), [keyboards](https://developer.apple.com/design/human-interface-guidelines/keyboards), [accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility), [split-view diagram](https://developer.apple.com/tutorials/images/com.apple.HIG/components-split-view-intro@2x.png), [toolbar grouping diagram](https://developer.apple.com/tutorials/images/com.apple.HIG/toolbars-layout-grouping-correct@2x.png) | The illustration treats sidebar, canvas and inspector as different jobs with independent widths. The toolbar example groups related commands. Menus and keyboard conventions bound what should be global versus contextual. | Use platform window decorations, menus and shortcut conventions in production; never make pointer, color, or a macOS modifier essential. Split views collapse or drill in before clipping content. |
