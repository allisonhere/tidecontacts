# What TideContacts will not copy

| Reject | Why | Prefer |
| --- | --- | --- |
| Navbar + large title + uniform grid of cards for every workspace | Makes location, highlights and supporting evidence compete; forces horizontal reading of results that are records. | One focal decision, followed by a ledger, investigation surface or action queue. Use different compositions for different jobs. |
| Recreating a reference product pixel-for-pixel | A competitor's brand and control density encode their jobs, not this CRM's. Borrowed artwork also cannot ship without rights. | Adopt hierarchy and interaction patterns only. Use Tide's own ink, paper, accent and bounded spacing, and native window controls. |
| Gray-on-gray as the only signal for unfocused controls | Low contrast leaves names hard to read. Color alone is not enough for selection, status or warning. | Marker or text, legible contrast, and distinct keyboard focus; quieter type only for secondary context. |
| Pretty but unsourced analytics | Estimates become numbers users trust with decisions. Truncated bars and mixed currencies imply false rankings. | Zero-based value bars, period and currency labels, exact values, source-record drill, explicit missing/zero distinction and wording that separates forecasts from booked values. |
| A global command palette that replaces visible actions | It rewards memorization and hides what is safe or possible from the current record. | Contextual, named actions; a visible palette for search/shortcuts; predictable focus return. |
| Always-on editors and stacked dialogs | Narrow panes, stale edit state, inaccessible escape paths. | Local disclosure, one active modal, return to the source context; act only after explicit intent. |
| Reaching `.db`, extension data or MCP from a demo page | Circumvents the existing authorization boundary and distorts visual tests with uncontrolled data. | Static fictional fixtures for visual design; the actual app only through an authorized future service adapter. |
| Building the entire product before the visual decision | Encourages premature shared components and makes the most reasonable redesign expensive. | Compare the same evidence task across hypotheses, then promote only tested components. |
