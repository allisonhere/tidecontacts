# TideContacts status

TideContacts is a standalone, offline-first terminal CRM with a shared TideMail address-book plugin. All eight workspaces are functional. The current SQLite schema is **5**.

## Working

- **Activity creation:** `A`, Activities `n`, Log meeting/call/note and follow-up recording open the labeled activity modal, with searchable links and preserved context. One-line activity capture remains optional in the palette.
- **Task creation:** `T` anywhere and `n` in Tasks open the labeled task modal, with status/priority choices and searchable person/organization/project links. Conversion preserves source links. One-line task capture remains an optional palette command.
- **Contacts and CRM:** people, organizations, methods, memberships, relationships, notes, custom fields, revisions/history, tombstones, undo, search, contact merge, activity timeline, tasks/recurrence/reminders, follow-ups, projects, pipelines, dossier, People Inbox, Radar and collections. [CRM guide](docs/crm-guide.md)
- **Import modal:** source chooser, file browser with `.` hidden-file toggle (off by default), path entry, mapping, dry-run preview, confirmation and results. Six active sources appear first: CSV, vCard, CRM JSON, Mutt/NeoMutt aliases, khard/vdirsyncer folders, and Google Contacts. Eight planned provider entries are dimmed and disabled. [Import guide](docs/import-export.md)
- **Connected vCard folders and Google accounts:** confirmed connections, startup/manual/plugin refresh, stable UID identity, atomic updates/removals/reconnect, read-only storage protection and last-good recovery on scan failure. A Google account connects with an email and an app password (requires 2-Step Verification); the password is stored in the OS keychain, never in the database or a config file, and contacts sync read-only over CardDAV. Local contacts remain separate; source files/accounts are never written to. [Folder guide](docs/vcard-directories.md)
- **TideMail plugin:** simple People view, local add/edit, search, compose, recent correspondence, read-only folder labels, `r` refresh, Ctrl+T external lookup with all email addresses, and bundled Advanced CRM. The standalone app need not run. Settings cover default view, real/demo profile and connection checks. TideMail local contacts stay separate. Requires a compatible TideMail source/binary. [Plugin guide](docs/tidemail-plugin.md)
- **TideMail activity connector:** opt-in read-only cache scan, Message-ID deduplication, participant linking to existing contacts and last-sync status. No bodies/attachments or automatic contact creation. [README](README.md#tidemail-connector-phase-4)
- **Scripting:** versioned JSON commands for contacts, organizations, tasks, activities, projects, pipelines/items, CRM archives and schema discovery. Revision/token checks prevent stale writes. Directory-owned contacts are read-only. [CLI guide](docs/cli.md)
- **aerc / NeoMutt:** read-only recipient queries and explicit sender capture. NeoMutt supports searched completion; the safe aerc configuration returns a candidate list because upstream substitutes query text into a shell without quoting. These commands query cached contacts and never refresh folders. [Mail-client guide](docs/mail-clients.md)
- **Forms:** creation/edit forms keep the same vertical height with footer hints at the bottom, shrinking for short terminals; input rows are single-spaced across contacts/organizations, tasks, activities, projects and pipelines. Up/Down moves between single-line inputs; Left/Right edits text or changes choices. Contact-editor hints label F5 as previous section and F6 as next section.
- **Navigation and appearance:** three columns at 120 columns, menu/modal navigation, TideUI help browser, searchable themes with live preview and Match TideMail for supported installed palettes.
- **Settings:** TideMail-style category sidebar and detail pane, with a one-pane fallback for narrow terminals. Display and startup preferences persist per profile; Radar, address books, extensions and MCP reuse their existing controls.
- **Extensions (Phase 3A):** optional subprocess extensions with validated manifests, explicit permission approval, default-deny host API, capability registry, best-effort typed events, private extension storage, host-rendered palette commands and dossier panels, a management modal (palette → *Manage extensions…*), and `extensions`/`capabilities` JSON CLI commands. Includes the read-only *Relationship Digest* example. Permissions are API authorization, not an OS sandbox. No commercial functionality, licensing or entitlements beyond the Community provider exist. [Guide](docs/extensions/README.md) · [Spec](docs/extensions/specification.md) · [Security](docs/extensions/security.md) · [ADRs](docs/adr/phase3a-extensions.md)
- **Extension contributions (Phase 3B host):** extensions can contribute a workspace (declarative views, forms, actions), JSON CLI resources, People Inbox signals, namespaced events and a private SQL data directory; per-capability entitlements; a development entitlement provider (not a licence). The first consumer is the separate private *TideContacts Professional: Sales* extension. [Spec §9](docs/extensions/specification.md)
- **Business dashboards (Phase 3C host):** declarative panels and terminal-cell charts, adaptive layouts, keyboard drill-down with return to the selected record, shared People Inbox and engagement calls, and explicit raw CLI report output. These are optional extension surfaces; the Community schema and record access are unchanged. [Host 0.4.0 / protocol v1](docs/extensions/specification.md#10-panel-views-and-shared-attention-host-040-api-v1)
- **Durable events (Phase 3D host):** supported CRM writes append identifiers and typed changes in the same SQLite transaction. Approved extensions pull declared topics with checkpoints, retry, dead letters and explicit replay. [Spec §11](docs/extensions/specification.md#11-durable-event-journal-host-050-api-v1)
- **Scoped rule integration (Phase 3D host):** approved extensions page typed CRM facts, check effective permissions, and request scoped local writes. Declarative workspace state supports keyboard editors. [Spec §§12–13](docs/extensions/specification.md#12-scoped-record-evaluation-host-060-api-v1)
- **Demo:** isolated fictional contacts/CRM, paired TideMail demo, reset support. Live activity sync, folder connections and desktop notifications are disabled.
- **Community MCP (Phase 3D host):** opt-in stdio server, revisioned per-profile grants, bounded CRM projections, scoped writes, protocol diagnostics, and a local content-free audit. Optional Professional tools require separate extension approval and entitlements. [Setup](docs/mcp.md).
- **Graphical clients (Phase 4C):** `cmd/tidecontacts-web` serves an authenticated loopback JSON API (`internal/webapp`; launch-specific bearer token, exact Host, no CORS, bounded requests, revision-bound writes) for a Svelte browser client (`web/`, embedded with `make web`) and a Qt Quick Community desktop client (`desktop/`). Optional Professional views are read-only and reach the approved extension only through a closed set of authorized reads (`ext.GraphicalActions`); there is no raw command path. Feature coverage and gaps: [docs/FEATURE-PARITY.md](docs/FEATURE-PARITY.md); design record: [docs/design](docs/design/DESIGN.md).

## Remaining limits

Extensions: no OS sandbox, per-process resource limits, signing, or installer.
The legacy push bus remains best-effort. The durable journal covers only listed
transactional writes; no folder/Google refresh events. Due signals are
evaluated conditions, not synthesized persisted events.


Direct CardDAV/server synchronization is implemented only for Google; every other provider still goes through vdirsyncer or a local vCard folder. Calling khard as a query command, provider-specific importers shown as coming soon, iCalendar import, durable CRM undo, ASCII-only glyph mode and AI remain deferred. Mouse support selects or focuses panes and rows; logs do not rotate.

## Verification and installation

Unit, integration and race tests cover domain/storage/CLI/TUI/bridge behavior, migrations, optimistic conflicts, directory ownership, updates, deletions, disconnect/reconnect and failed scans. Golden frames and bounded-render tests cover terminal layouts. Real terminal and executable smoke scripts cover CRM, imports, scripting, recipient formats and folder refresh with TideContacts stopped.

`make check` runs formatting, build, vet and short race tests. `make smoke-extensions` exercises discovery, approval, host API denial, capability discovery and hung-extension isolation with the real binary. `make smoke`, `make smoke-directories`, `make smoke-cli` and `make smoke-mail-clients` exercise isolated profiles. The TideMail integration has its own focused tests in that repository. See [architecture](docs/architecture.md) and [migration/backup](docs/migration-backup.md).

The current features are built and installed locally. Importer, directory and form updates are prepared on a dedicated feature branch for PR review; local availability does not imply a published release.
